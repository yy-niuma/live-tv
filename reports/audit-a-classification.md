## 二、架构问题

### 2.1 三个函数的调用关系与优先级链条

```
grouper.py:78  _match_group(ch)
   └─ categorizer.py:92  →  categorize(name, group, logo)
                              │
                              ├─ 1  CCTV/CETV            :473-483   return 📺 央视频道
                              ├─ 2  PROVINCE_KEYWORDS    :486-488   return 📺 <省>      ← 32 键 217 正则
                              ├─ 3  台湾 tw_kw           :491-506   return 🇹🇼 台湾
                              ├─ 4  overseas_satellite   :510-519   return 📡 卫视频道  ← 含裸 "atv"
                              ├─ 5  TVB/ViuTV/RTHK/HOY/Now/有线 :524-546
                              ├─ 5b 澳门                 :549-550
                              ├─ 6  电影 movie_kw        :553-565
                              ├─ 7  音乐 music_kw        :568-576
                              ├─ 8  国际 intl_kw         :579-594   return 🌐 国际频道
                              ├─ 9  新闻 news_kw         :597-609
                              ├─10  儿童 kids_kw         :612-623
                              ├─11  综艺 variety_kw      :626-635
                              ├─12  体育 sport_kw        :638-655
                              ├─13  纪录片 doc_kw        :658-667
                              └─14  兜底 :669  return recategorize_others(name, group, logo)
                                        │
                                        ├─1 logo 命中 LOGO_REGION_PATTERNS  :379-382  ← 优先级高于一切语义
                                        ├─2 PROVINCE_KEYWORDS（**第二次遍历**）:385-387
                                        ├─3 is_hk_region()  →  TW/MO/TVB 二次判定 :390-443
                                        │      └─ 内部再次重写 tw_kw/hk_kw 正则（与 :491/:132 重复但不一致）
                                        ├─4 GROUP_TITLE_EN_MAPPING（英文 group 映射）:446-457
                                        └─5 默认 :460  return "🌐 国际"
```

`is_hk_region()`（`:101-236`）与 `categorize()`（`:466-670`）是**并列的第二套判定体系**，由 `generator.py:122` 在生成 HK 播放列表时独立调用一次。它自己的内部顺序是：

```
tvb_kw_exact(IGNORECASE) :199  >  exclude(大小写敏感) :204  >  CCTV/CETV 硬排除 :209-215
  >  hk_exact+tw_exact+mo_exact(大小写敏感) :218  >  non_hk_groups + cat 名否决 :223-234  >  False
```

### 2.2 结构缺陷（具体，不是泛泛而谈）

**缺陷 A：同一批正则被抄了三份，且三份不一致。**

| 位置 | 台湾关键词 | 澳门 | 大小写 |
|---|---|---|---|
| `:132-142` `tw_exact` | `tvbs…华视…` | — | 大小写敏感（死） |
| `:394-397` `recategorize.tw_kw` | 另一份 | `:401` | IGNORECASE |
| `:491-504` `categorize.tw_kw` | 第三份（多了 `台湾台`） | `:549` | IGNORECASE |

后果实测：`FTV`、`CNA` 出现在 `🇹🇼 台湾` 里，靠的是 `:501` 的 `r"\bftv\b"`；但 `recategorize_others` 的 `:396` 写的是 `r"ftv\\b"`（双反斜杠，死模式），同一名字走兜底路径就会漏。

**缺陷 B：优先级链条与语义重要性无关，只与代码书写顺序有关。**

- 第 2 步（省名枚举）**先于**第 6-14 步（题材）。所以 `广东体育`→`📺 广东`、`江苏体育`→`📺 江苏`、`浙江体育`→`📺 浙江`，同一个"省级体育频道"概念落到省分类里；而 `四川体育`、`五星体育` 因为 `sport_kw`（`:642`）只认 `体育台`/`体育频道` 而**不认裸 `XX体育`**，直接掉进 `🌐 国际`。三条路径、三种结果，全由关键词表里恰好写了什么决定。
- 第 4 步 `r"atv"` **先于**第 6-14 步所有题材判定，所以任何 `...aTV` 结尾的频道无论题材一律变卫视。
- 第 1 步 logo（`recategorize_others:379`）**先于**所有语义判定，所以 `gitee.com/suxuang` 的频道全部 → `🇨🇳 中国源`，`epg.112114.xyz/logo/TVB` → `📺 TVB`。logo 是**分发渠道**信息，用它决定**内容分类**是范畴错误。

**缺陷 C：同一个字符串常量既是"分类名"又是"匹配输入"。**

`_match`（`:55`）把 `name + group` 拼成一个字符串再跑正则。`group` 是**源列表的 group-title**，于是：

```
>>> categorize('嘉佳卡通','Others')  → '🌐 国际'
>>> categorize('嘉佳卡通','Kids')    → '🧸 儿童频道'
>>> categorize('嘉佳卡通','动画')    → '🌐 国际'      # 中文 group 反而不认
```

对 1168 个真实频道名做敏感性测试：

| 把 group 从 `Others` 换成 | 分类结果改变的频道数 |
|---|---|
| `Movies` | **873 / 1168（74.7%）** |
| `News` | **680 / 1168（58.2%）** |

**即：分类结果 3/4 由"源列表怎么分组"决定，而不是由"频道是什么"决定。** 而 `normalize.merge_duplicate_channels`（`normalize.py:273-281`）在合并同名频道时，`group` 取自 URL 优先级最高的那条（`merged_ch = best.copy()`），所以**同一频道最终落在哪一类，取决于哪条 URL 的 CDN 更快**。这是随机性来源。

**缺陷 D：三处"兜底"方向互相矛盾。**

| 位置 | 兜底目标 | 语义 |
|---|---|---|
| `:594` | `🌐 国际频道` | 真·国际（BBC/CNN/NHK） |
| `:443` / `:460` | `🌐 国际` | 未知 |
| `:434` | `📺 TVB` | "unknown group 但不是明显非HK → 暂归 HK" |

### 2.3 「同一频道名走不同路径得到不同分类」—— 实测

**(a) 单次幂等：通过。** 把 1168 个真实频道名跑 `categorize(name,'Others')` 得 `a`，再跑 `categorize(name, a)` 得 `b`：

```
总数 1168, 二次分类结果不同: 0 (0.0%)
```

因为 `:669 → recategorize_others` 也是纯函数，且分类名本身不含任何关键词（`📺 北京` 不会被 `PROVINCE_KEYWORDS` 匹配）。**这一项没有缺陷**，任务书的怀疑不成立。

**(b) 但把分类名当 group 回灌，信息全丢**（真实场景：`output/all_merged.m3u` 本身被当作源再喂回去，这是 IPTV 聚合项目极常见的操作）：

```
group='📺 北京' → '🌐 国际'      group='📡 卫视频道' → '🌐 国际'
group='📺 TVB'  → '🌐 国际'      group='📺 央视频道' → '🌐 国际'
（33 个分类全部 → 🌐 国际）
```

**(c) 分类名分裂（P0-5）造成真·非幂等**：

```
>>> categorize('hkdtmb','Music')      → '🎵 音乐'      # :441，不在 CATEGORY_ORDER
>>> categorize('hkdtmb','MTV')        → '🎵 音乐频道'  # :576
```

**(d) 分类名与排序表对不上**：代码理论上可产出 **52** 个分类名，其中 `🌐 国际`、`🎵 音乐` 两个不在 `CATEGORY_ORDER`；反过来 `CATEGORY_ORDER` 里有 **12 个分类代码永远产不出来**：

```
🌍 欧洲 🌍 中东 🌍 非洲 🌎 拉丁美洲 🌏 大洋洲 📺 其他
```

`generator.py:37-38` 精心排列的"国际细分"顺序表是一张**幻想清单**，代码里没有任何一条路径会返回它们。

### 2.4 `_match()` 的"懒编译缓存"—— 不存在

任务书说"48 行附近懒编译缓存"。实际 `categorizer.py:48-56`：

```python
def _match(name_lower: str, group_lower: str, patterns: list) -> bool:
    full = name_lower + " " + group_lower
    return any(re.search(p, full, re.IGNORECASE) for p in patterns)
```

**没有任何 `re.compile`、没有 `functools.lru_cache`、没有模块级 `_CACHE` 字典。** 它依赖的是 CPython `re` 模块自带的 `re._cache`，而那个缓存上限是 **512**：

```
distinct regex pattern 总数: 566        /  re._MAXCACHE = 512
PROVINCE_KEYWORDS: 32 省, 217 条模式
```

566 > 512，**缓存必然饱和并抖动**。实测（1168 个真实频道名）：

| 场景 | 耗时 | 单频道 |
|---|---:|---:|
| 热缓存（独立进程，只 import categorizer） | **7.94 s** | 6.80 ms |
| `re.purge()` 后 | 9.09 s | 7.78 ms |
| `re._MAXCACHE=1`（等效关闭缓存） | 28.05 s | 24.01 ms |
| 完整脚本（`reports/verify_classification.py`，import 了 generator 后缓存更挤） | **14.21 s** | 12.17 ms |

- 缓存只带来 **3.5x** 加速（如果真做了显式编译缓存，这个比值应该是 30-50x）。
- **同一个进程内两次测得的单频道耗时相差 1.8 倍（6.80 vs 12.17 ms）** —— 这个不稳定性本身就是缓存抖动的直接证据：命中率取决于被测语料碰巧落进 512 个槽位的哪一段。
- 按 8450 个频道外推：**57 s ~ 103 s**。任务书记载的"加懒编译后 6.1 秒"与代码不符。
- 每次调用 `_match` 时 `full = name_lower + " " + group_lower` 都重新拼一次字符串（1168×14 步 ≈ 16k 次无谓拼接）。

**结论：缓存"生效"只是标准库的副作用，不是设计；且已饱和。这是 P1，不是优化项。**

## 四、重构方案

### 4.1 判断：该换架构

670 行、217 条枚举正则、7 条已知 BUG、同一批正则抄三份、3.5x 而不是 40x 的性能、18% 死代码、0 测试 —— 这不是"再补几条关键词"能收敛的状态。

但要说清一件事：**当前失败的根因不是"关键词不够多"，而是缺少两个正交的维度。**

现在一个 if 链在同时回答三个互不相关的问题：

1. **它是哪个台？**（CCTV / 湖南卫视 / 萧山台 / BBC）
2. **它是什么题材？**（新闻 / 电影 / 体育 / 儿童）
3. **它的地理归属？**（中国大陆省级 / 市县 / 港澳台 / 境外）

三者被压进一个 `return`，所以每加一条关键词都在三个维度上同时下注 —— 修 `广东体育` 就影响 `体育频道` 的总量，修 `atv` 就影响 `卫视`。**这才是"修一个碰坏另一个"的机制性原因。** 补关键词只会让下注次数变多。

### 4.2 目标结构

```
src/group/
├── classify.py          # 新入口，~120 行，纯函数 + 可解释返回
├── resolver/
│   ├── geo.py           # 地名解析：name → Geo(province, city, county, level)
│   ├── genre.py         # 题材解析：name+source_group → Genre

│   └── region.py        # 港/台/澳/境外判定（唯一一份，不再抄三份）
├── rules/
│   ├── geo.yaml         # 省/市/区县名表 + 归属
│   ├── brand.yaml       # 品牌 → 分类（含 flag 边界）
│   └── genre.yaml       # 题材规则（有序，带 priority + stop）
├── compose.py           # (brand, geo, genre) → 分类名，矩阵可配置

```

**核心不变式：`classify()` 返回的不是字符串，而是可解释对象。**

```python
@dataclass(frozen=True)
class Explanation:
    category: str          # 最终分类名
    rule_id: str           # 命中的规则 id，如 "brand.tvbs" / "geo.zhejiang" / "genre.sport"
    stage: str             # brand | geo | genre | fallback
    inputs: dict           # 供测试断言
```

`grouper.py:92` 只取 `.category`，调用方零改动；测试和 debug 靠 `rule_id` 一眼定位。

### 4.3 三个正交解析器（这才是修复 3870 的正解）

**geo.yaml —— 地名表，一条规则覆盖一个省的无限种频道名：**

```yaml
# rules/geo.yaml
provinces:
  - id: zhejiang
    name: "浙江"
    aliases: ["浙江", "之江"]
    cities:
      - { id: hangzhou, name: "杭州", aliases: ["杭州", "余杭", "萧山", "临平", "富阳"] }
      - { id: ningbo,   name: "宁波", aliases: ["宁波", "鄞州", "余姚", "慈溪"] }
      - { id: wenzhou,  name: "温州", aliases: ["温州", "瓯海", "乐清"] }
    # 派生：任何以 province.name 开头且不以城市名开头的名字 → 省级
  - id: shanghai
    name: "上海"
    brands: ["东方卫视", "上海东方", "五星体育", "哈哈炫动", "第一财经"]
```

解析规则（`resolver/geo.py`）：

```python
def resolve_geo(name: str) -> Geo | None:
    # 1. 精确品牌前缀（"东方卫视" → 上海省级，必须靠 brands 表，不能靠子串）
    # 2. 省级前缀：name.startswith(p.name) 且 !any(city prefix) → level="province"
    # 3. 城市前缀 → level="city", province=p
    # 4. 区县别名 → level="county"
    # 5. 无任何命中 → None（进入 fallback，绝不返回"国际"）
```

这一条直接消灭：
- `浙江经视` / `浙江教科` / `浙江生活` / `浙江国际` / `浙江休闲台` / `浙江数码时代` → `📺 浙江`（前缀规则，无需枚举）
- `萧山综合` / `余杭未来E` → 浙江省杭州市（`level=county` → `📺 浙江·地方`）
- `哈尔滨新闻综合` → `📺 黑龙江·地方`
- `东方卫视` → `📺 上海`（靠 `brands`，这是枚举**唯一**该出现的地方：品牌名不遵循地理前缀）

**genre.yaml —— 题材规则表，有序、显式、可测：**

```yaml
# rules/genre.yaml —— 按 priority 升序，first-match
- id: genre.sport
  priority: 10
  name_any: ["体育", "足球", "篮球", "高尔夫", "网球", "赛车", "搏击", "格斗",
             "奥运", "欧冠", "英超", "意甲", "西甲", "德甲", "法甲", "中超", "亚冠"]
  name_boundary_any: ["espn", "nba", "cba", "bein"]
  source_group_in: ["sports", "outdoor"]
  exclude_name_any: ["电影", "影视"]        # ← 修 P1 "电影_赛车"
  target: "⚽ 体育频道"

- id: genre.movie
  priority: 20
  name_any: ["电影", "影视", "影城", "好莱坞", "影院"]
  name_boundary_any: ["hbo", "cinemax", "amc", "mgm", "paramount"]
  source_group_in: ["movies", "classic"]
  target: "🎬 电影频道"

- id: genre.satellite
  priority: 5                               # ← 修 P0-7，必须早于 province
  name_regex: '^\S{2,5}卫视$'
  target: "📡 卫视频道"
```

关键点：`exclude_name_any` 让 `电影_赛车` 不再进体育；`name_regex` 让所有 `X卫视` 自动归位而不用枚举；`source_group_in` 是**白名单枚举**（`["sports"]`）而不是 `name + group` 模糊拼串 —— 这样 group 污染从"任何 group 都参与"降到"只认白名单里的精确值"。

**brand.yaml —— 品牌优先，带显式边界：**

```yaml
- id: brand.cctv
  priority: 1
  name_regex: '^cctv[\-_ ]?\d+$|^cctv[\-_ ]?(news|english|4k|8k)$'
  target: "📺 央视频道"
- id: brand.tvbs
  priority: 2
  name_regex: '(?<![a-z])tvbs(?![a-z])'      # ← 显式拉丁边界，不是裸子串
  target: "🇹🇼 台湾"
- id: brand.atv_asian
  priority: 2
  name_regex: '(?<![a-z])(atv|asia television)(?![a-z])'   # ← 修 P0-2
  source_group_in: ["hong kong", "hk"]
  target: "📡 卫视频道"
```

**每个 pattern 都是单个正则，且测试强制要求它能匹配自己的正样本、不匹配自己的反样本。** 这直接杀死 `\\b` 双反斜杠和大小写敏感两类死模式（P0-8/P0-9）—— 因为死模式在测试里必然失败。

### 4.4 组合阶段：三维度 → 分类名（矩阵显式可配）

```python
# compose.py
def compose(brand, geo, genre, cfg) -> Explanation:
    if brand:                                    # 品牌最高优先
        return brand
    if geo and geo.level == "province" and genre in cfg.province_keeps:
        return geo.category                      # 浙江体育 → 📺 浙江
    if genre:
        return genre.target                      # 五星体育 → ⚽ 体育频道
    if geo:
        return geo.category                      # 萧山综合 → 📺 浙江·地方
    return Explanation(category=cfg.fallback, rule_id="fallback.unclassified", stage="fallback")
```

`province_keeps` 在配置里显式列出"哪些题材留在省分类里"，不再由 if 链的书写顺序决定。想改 `浙江体育` 归体育，改一行 YAML，不碰代码。

`fallback` = `📺 未分类`（**不是** `🌐 国际`）。国际分类只能由 `brand`/`genre` 的境外规则产生 —— 从架构上杜绝"国际 3870"。
